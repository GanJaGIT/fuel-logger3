# Ревью старой версии FuelLog (3.3.0)

Стек: WPF, .NET 10, CommunityToolkit.Mvvm, ClosedXML, хранение в JSON.
Сам стек выбран удачно. Проблемы лежат в логике расчётов, хранении данных и архитектуре.

## 1. Ошибки в расчётах (критично: отчёт не совпадает с образцом)

| # | Где | Проблема |
|---|-----|----------|
| 1.1 | `CalculationService` | «Заправки» считаются как `литры / суммарный объём баков ВСЕХ задействованных подразделений`. В образце: `кг / масса заправки своего уровня` (подразделение → рп → итог). Пример из образца: 91,26 кг / 766 кг = 0,12 запр. |
| 1.2 | `FuelReportService` | «Масса заправки» = объём баков **первой** машины × жёстко заданные 0,80 / 0,75. Должна быть сумма по всей технике подразделения (группы) с плотностью из настроек. |
| 1.3 | `FuelReportService` | В итогах по группе и в общем итоге масса берётся у первой строки, а заправки суммируются. По образцу заправки = кг / масса уровня (1360,44 / 2987 = 0,46). |
| 1.4 | `CalculationService` | Потерянная машина одновременно расходует топливо на марш/работу **и** списывает полный бак. Справка программы утверждает, что потерянная машина задачу не выполняет. Код и документация противоречат друг другу. |
| 1.5 | `ProjectSettings` | Плотности по умолчанию АБ 0,80 и ДТ 0,75. Похоже на перепутанные значения: у ДТ плотность выше, чем у АБ. |
| 1.6 | Отчёт | «Дата выполнения задачи» = время нажатия кнопки «Рассчитать». У задачи нет своей даты. |
| 1.7 | Отчёт | Итоги по подразделениям выводятся все разом в конце листа, а не после строк своего подразделения, как в образце. Группы сортируются по алфавиту, а не в порядке структуры. |
| 1.8 | `MathViewModel` | Соответствие «подразделение → рп» строится по **имени** подразделения. Два подразделения «1 рдн» в разных рп склеиваются в одно. |

## 2. Потеря данных (критично)

- **Задачи не сохраняются.** Они живут только в памяти `MathViewModel` и теряются при закрытии программы.
- Кнопка «Сохранить» в редакторе техники подразделения ничего не пишет на диск (`// TODO: Сохранить на диск`).
- Запись файлов не атомарная (`File.WriteAllText`). Сбой питания во время записи оставляет повреждённый файл. Резервных копий нет.
- Подразделения дублируются в `*.gsmproject` и `Data/units.json`. При рассинхронизации побеждает `units.json`.
- При загрузке «лишние» шаблоны молча **удаляются с диска** (`TemplateViewModel.LoadOrCreateTemplate`).
- Если в «последних проектах» не найден файл, программа предлагает удалить его из списка, а вместо этого добавляет проект обратно.
- Переименование проекта в настройках оставляет старый файл (новый создаётся при следующем сохранении).

## 3. Архитектура и качество кода

- Параметры техники (баки, нормы) **копируются** в каждое подразделение и в каждую задачу. Исправление нормы в справочнике не доходит до уже добавленной техники.
- Сервисы достаются через `((App)App.Current).Services`. ViewModel создают окна и вызывают `MessageBox`. Поэтому код невозможно тестировать, тестов нет.
- ID в виде `int` с ручным вычислением `Max()+1`. ID задачи = `Tasks.Count + 1`, что даёт дубликаты после удаления.
- Мёртвый код: `ExcelReportService`, `JsonUnitRepository` (заглушка), `TaskVehicle`, `SelectedUnits`, `SaveProjectAs` (`NotImplementedException`), лишний `using DocumentFormat.OpenXml.Bibliography`.
- Перечисление `UnitType` смешивает воинские части и категории техники. Базовые группы (1–4 РП, РТБ, ТРБ, ПОО) зашиты в код, их нельзя переименовать или добавить новые.
- Предварительные (preview) версии пакетов `Microsoft.Extensions.DependencyInjection`/`System.Text.Json 11.0.0-preview` в боевой сборке.
- `MessageBox` «Успешно» после каждого действия (добавление марки, сохранение и т.д.) мешает работе.
- Огромная справка в XAML (72 КБ), которую трудно поддерживать.

## 4. Удобство работы

- Количество доступной техники уменьшается на всё, что задействовано во **всех** задачах, независимо от даты. Одна и та же машина в образце выполняет 4 задачи за день, а старая программа такое запрещает.
- Нет копирования задачи, хотя задачи с одинаковым составом повторяются.
- Нет предпросмотра результата до формирования Excel.
- Нет переноса справочника техники между ПК, кроме ручного копирования `.gsmtemplate`.
